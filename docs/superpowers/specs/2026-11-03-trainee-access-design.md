# Доступ стажёров по общему коду

Дата: 2026-11-03. Затрагивает legacy-back и legacy-frontend.

## Назначение
Стажёры читают выбранные карточки без регистрации и без создания пользователя в БД.

## Согласованные требования
- Общий код генерируется на backend и хранится в БД, сохраняется после перезапуска.
- Получать текущий код и генерировать новый могут только admin/админ, председатель, председатель студсовета и заместители председателя. Проверка на backend по должности действующего авторизованного пользователя; интерфейс повторяет её для видимости ссылки.
- Отдельная страница «Доступ стажёров», переход через шапку для указанных должностей. Показывает текущий код, копирование, генерацию нового кода. До первой генерации вход стажёров закрыт.
- На обычной странице входа кнопка «Я стажёр» с милым анимированным енотом. Кнопка открывает отдельную страницу ввода кода.
- Сессия стажёра действует 30 дней. Смена кода немедленно делает недействительными ранее выданные токены при следующем запросе к API. Старый код больше не принимается.
- У стажёров нет аккаунта, кнопок аккаунта и выхода. Обычный вход сотрудников сохраняется.
- При создании и редактировании карточки настраивается отдельный флаг «Доступна стажёрам». В существующих карточках по умолчанию выключен. Флаг действует независимо от ограничений карточки для сотрудников.

## Предлагаемая реализация
- Отдельный тип JWT для стажёра, со сроком exp и версией кода. Каждый запрос стажёра проверяет подпись, срок и текущую версию в БД. Обычная авторизация не принимает токен стажёра как пользовательский.
- Отдельные endpoints гостевого чтения и входа; существующие endpoints управления остаются доступны только обычным пользователям с соответствующими правами.
- Стажёру доступны только отмеченные карточки и категории, содержащие эти карточки. Ответы не содержат списков разрешённых логинов и должностей.
- Пользователи, профили, отделы, комментарии и журнал действий недоступны. Динамический Markdown-блок :::users в режиме стажёра заменяется нейтральной заглушкой без запросов данных пользователей. Остальной Markdown сохраняется.
- При истечении/отзыве сессии переход на страницу входа стажёра с понятным сообщением. Защита действует при прямом обращении к карточке и API.
- Новый криптографически случайный код; смена кода и его версии в одной транзакции. Не помещать код в URL или логи.
- Код хранится на сервере: отображение доступно исключительно управляющим должностям. Секреты сервера и локальный app.db не включать в коммиты.
- Для енота создать отдельный милый растровый рисунок и анимировать его в интерфейсе; учитывать prefers-reduced-motion. В проекте уже есть SVG-енот, но пользователь запросил поиск в интернете или генерацию нового изображения.

## Подходы
Выбранная рекомендация: отдельная гостевая сессия и API чтения. Даёт явную границу доступа и не создаёт фиктивного пользователя.
Альтернатива — общий аккаунт стажёра: противоречит требованию отсутствия аккаунта, смешивает историю и пользовательские права.
Альтернатива — передавать общий код с каждым запросом: разносит сам код по клиенту и не реализует отдельную 30-дневную сессию.

## Проверки
Права генерации (admin, председатель, замы; отказ секретарю, участнику и стажёру); срок 30 дней; отзыв старых токенов при смене кода; запрет старого кода; сохранение кода после рестарта; отсутствие доступа к закрытым карточкам напрямую и в списках; запрет пользовательских и изменяющих endpoints для стажёра; отсутствие запросов :::users; обычная авторизация продолжает работать; сборка TypeScript/Vite и ESLint.

## Ограничения
Не заменять и не пересоздавать существующий app.db. Обновить схему идемпотентно, с учётом нескольких gunicorn workers. Пуш/деплой не входят в реализацию без отдельного поручения.
